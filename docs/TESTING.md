# テスト方針

## 何を守るためのテストか

優先順位は次のとおりです。上のものが壊れる方が影響が大きいためです。

1. **出力ファイルの正しさ** — QMK / KiCad / VIA / KLE。壊れると基板やファームが作れない
2. **データを失わないこと** — 保存・読み込み・移行
3. **編集操作の正しさ** — 座標・回転・マトリクス
4. **UI の動作** — 操作できること

## 構成

| 種類 | ツール | 対象 | 置き場所 |
|---|---|---|---|
| ユニット | Vitest | `src/core/` `src/io/` (純関数) | `tests/unit/` |
| コンポーネント | Vitest + Testing Library | `src/ui/` の個別部品 | `tests/unit/ui/` |
| E2E | Playwright (Chromium) | 実際の操作 | `tests/e2e/` |
| 性能 | Vitest (計測付き) | 大量キーでの操作 | `tests/perf/` |

`src/core/` と `src/io/` はブラウザ API を使わないため、jsdom を用意せず
Node 環境で高速に回せます。これがレイヤ分割の実利です
([adr/0005-core-ui-separation.md](adr/0005-core-ui-separation.md))。

## ゴールデンファイル方式

フォーマット出力のテストは、期待する出力ファイルを**リポジトリに置いて全文比較**します。

```
tests/fixtures/
├── layouts/                    共通の入力レイアウト (プロジェクト JSON)
│   ├── 4x4-macropad.json
│   ├── ansi-104.json
│   ├── iso-105.json
│   ├── split-ergo.json
│   └── special-chars.json
├── kle/
│   ├── ansi-104.txt            KLE raw JSON の入力
│   └── ansi-104.expected.json  parse 結果のスナップショット
├── qmk/
│   └── ansi-104.info.json      期待する出力
├── kicad/
│   ├── 4x4-macropad.kicad_sch
│   └── 4x4-macropad.kicad_pcb
├── via/
├── ergogen/
└── project/
    ├── v0/                     旧 MKD 形式のサンプル (消さない)
    └── v1/
```

### 守ること

- **期待値ファイルを差分に合わせて黙って書き換えない。** 差分が出たら、
  それが意図した変更かを先に判断します。意図した変更なら、
  **何がどう変わったかを PR に書いた上で**更新します。
- 乱数・時刻を出力に含めない。UUID 生成関数と現在時刻は引数で差し替えられる形にし、
  テストでは固定値を返す実装を渡します
  ([formats/KICAD.md](formats/KICAD.md#バスとラベル))。
- JSON 出力は**パースしたオブジェクトの深い比較**、S 式と YAML は**文字列比較**。
  JSON は整形の差でテストが落ちても意味がなく、S 式と YAML は並び順や整形自体が
  意味を持つためです。

## ラウンドトリップテスト

KLE 互換の中核です。

```
① parse(kleText) → project        : スナップショットと一致するか
② serialize(project) → kleText'   : 出力できるか
③ parse(kleText') → project'      : project と project' が同値か
④ serialize(project') → kleText'' : kleText' と kleText'' が完全一致 (べき等) か
```

③ の「同値」は**モデル同士の比較**で判定します (文字列比較ではない)。
比較時に無視するもの: `id` (UUID は再生成される)、`createdAt` / `updatedAt`。

プロジェクト JSON では、`updatedAt` を除いて**完全一致**を要求します。

## ユニットテストで必ず押さえる点

### `core/geometry`

- 回転 0° / 90° / 180° / 270° / 15° での頂点と AABB
- `getRotatedRectAABB` の結果が `getRotatedRectPoints` から求めた AABB と一致すること
  (2 つの実装が独立しているため、相互検証になる)
- SAT: 接している / 少しだけ重なる / 完全に含む / 完全に離れている の 4 ケース
- 単位換算の往復 (`mmToU(uToMm(x)) === x`)
- スナップ: 負値、ちょうど半分の値 (`0.125` を `0.25` グリッドで)、スナップ無効時

### `core/matrix`

- 自動割り当ての基本 (格子配置)
- **並べ替えの安定性** — Y が `0.00 / 0.09 / 0.18` のように許容誤差の連鎖を作る配置で、
  何度実行しても同じ結果になること ([MATRIX.md](MATRIX.md#量子化を外してはいけない理由))
- 開始 Row / Col の指定
- 選択キーのみを対象にした場合、対象外のキーが変わらないこと
- 回転したキーを含む配置
- `decal` のキーが除外されること
- 検証機能: 重複 / 未割り当て / 欠番の検出

### `core/model`

- `migrate` の各版 (フィクスチャと 1 対 1)
- `validateProject` の各不変条件
- 編集コマンドの純粋性 (入力オブジェクトが変更されないこと)

### `io/*`

- 各形式のフィクスチャに対する出力一致
- 警告が期待どおり出ること (警告の一覧もスナップショットに含める)
- 異常入力: 空のレイアウト、キー 1 個、マトリクス未割り当て、
  刻印に `<` `"` `\n` バッククォート・絶対値の大きい座標

## E2E テスト

旧アプリの `e2e/` にあった観点を引き継ぎます。

| シナリオ | 内容 |
|---|---|
| 起動 | 空のキャンバスが表示され、コンソールにエラーが出ない |
| キー追加 | プリセットのクリックとドラッグ＆ドロップで追加できる |
| 複製 | 選択して複製すると、グリッド幅分ずれた位置に増える |
| 刻印編集 | インスペクタで入力するとキャンバスの表示が変わる |
| 複数選択とドラッグ | 3 個選択して動かすと相対位置が保たれる |
| 取り消し / やり直し | 移動・削除・追加それぞれで正しく戻る。ドラッグ 1 回が履歴 1 段になる |
| ショートカット | [UI_SPEC.md](UI_SPEC.md#キーボードショートカット) の全項目 |
| マトリクス自動割り当て | 実行後の Row / Col がインスペクタに反映される |
| プロジェクト管理 | 保存・切り替え・削除、リロード後もデータが残る |
| 取込 / 書出 | ファイルを取り込んで表示され、書き出したファイルの中身が期待どおり |
| テーマ切替 | ライト / ダークで表示が壊れない |

### ストアへのアクセス

旧アプリは E2E のために `components/DevStoreExporter.tsx` でストアを
`window` に露出させていました。本アプリでは行いません。代わりに:

- 表示・操作は `data-testid` を通じて検証する
- どうしても内部状態が必要な場合は、**開発ビルドのみ**で有効な
  `window.__APP_TEST__` を用意し、本番ビルドでは含めない (`import.meta.env.DEV` で分岐)

## 性能テスト

旧アプリのベンチマークと同じ基準を使います。1000 キーのレイアウトで:

| 操作 | 目標 |
|---|---|
| 初回描画 | 500ms 以内 |
| 全選択 | 100ms 以内 |
| 100 キーのドラッグ移動 (1 フレーム) | 16ms 以内 |
| 矩形選択の判定 | 50ms 以内 |
| 保存 (シリアライズ) | 200ms 以内 |
| 自動マトリクス割り当て | 200ms 以内 |

数値は環境で変わるため、**CI では絶対値で落とさず**、著しい悪化 (前回比 2 倍以上) を
警告として出します。ローカルでの計測手段として `npm run test:perf` を用意します。

## CI

`.github/workflows/ci.yml` で以下を順に実行します (旧アプリと同じ構成)。

```
lint → typecheck → test (ユニット) → test:e2e → build
```

Node は 22。`npm ci` でインストールします。E2E では Chromium のみ入れます
(`npx playwright install --with-deps chromium`)。

## レビュー時に確認すること

- 出力フォーマットの変更なのに、ゴールデンファイルの差分が PR 説明に無い
- 期待値ファイルだけが変わって、対応するコードの変更が無い
- 座標計算の変更なのに、回転を含むテストが増えていない
- `core` / `io` にブラウザ API が入り込んでいない
- 仕様の変更なのに `docs/` が更新されていない

## リリース前の手作業確認

自動化できない部分です。リリースごとに実施します。

1. **KiCad で開く** — 出力した zip を展開し、KiCad で回路図と基板を開く。
   エラー・警告が出ないこと。「回路図から基板を更新」を実行して整合が取れること。
2. **QMK Configurator に読み込む** — 出力した `info.json` を
   QMK Configurator にアップロードし、レイアウトが正しく表示されること。
3. **KLE との往復** — KLE で作ったレイアウトを取り込み、書き出したものを
   KLE に戻して同じ見た目になること。
4. **VIA に読み込む** — VIA の Design タブに定義ファイルを読み込み、
   キー配置とマトリクスが正しく表示されること。
5. **旧アプリのデータ** — 旧アプリでエクスポートした JSON を読み込み、
   レイアウトが再現されること。
6. **モバイル** — 実機のタブレット / スマートフォンでパン・ズーム・選択ができること。
