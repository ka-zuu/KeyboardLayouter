# 0005. ドメインロジックを UI から分離する

- 状態: 採用
- 日付: 2026-08-12

## 背景

旧アプリでは、アプリの中核となるロジックが Zustand ストア
(`store/useStore.ts`、約 500 行) と React コンポーネントの中に置かれていました。

具体的には:

- マトリクス自動割り当て (ソートと番号付け) がストアのアクションの中に直接書かれていた
- 旧フォーマットからのデータ移行が `loadProject` アクションの副作用として実行されていた
- キー追加時の重なり判定と回避が `LeftSidebar.tsx` (UI コンポーネント) の中にあった
- 座標変換 (画面 → レイアウト) が `LeftSidebar.tsx` と `MainCanvas.tsx` に
  それぞれ書かれていた

この結果、

- アルゴリズムを単体でテストできない。テストのために React の描画と
  ストアの初期化が必要になる
- 同じ計算が複数箇所に書かれ、片方だけ直される
- ロジックを読むために UI の事情 (サイドバーの幅など) を読む必要がある

という状態でした。実際、旧アプリのベンチマークテストは
アルゴリズムを検証するために React コンポーネントを描画しています。

## 選択肢

### 案 A: 現状の構成を維持し、規律で対処する

- 追加コストがない
- 規律は必ず緩む。旧アプリで実際に緩んだ

### 案 B: レイヤを分け、依存方向を lint で強制する

- ロジックを Node 環境で直接テストできる
- 追加コスト: ディレクトリ構成と lint 設定、そして「どちらに書くか」の判断

## 決定

**案 B** を採用します。依存の向きを次の一方向に固定します。

```
ui → state → core
io  → core
```

`src/core/` と `src/io/` には**ブラウザ API を書きません**。
`window` / `document` / `localStorage` / `indexedDB` / `alert` / DOM への参照は
`src/ui/` または `src/platform/` に閉じ込めます。

これは ESLint で機械的に強制します
([../BOOTSTRAP.md](../BOOTSTRAP.md#5-eslint) の `no-restricted-globals` と
`no-restricted-imports`)。規律ではなく仕組みで守るのが要点です。

### どちらに書くかの判断

| 内容 | 置き場所 |
|---|---|
| 座標の計算、当たり判定、単位換算 | `core/geometry` |
| マトリクスの割り当て・検証 | `core/matrix` |
| キー・プロジェクトの生成と変更 | `core/model`, `core/commands` |
| フォーマットの読み書き | `io/*` |
| ポインタ座標の取得、要素のサイズ測定 | `ui/hooks` |
| ファイルの保存・読み込み、IndexedDB、zip | `platform/*` |
| 「どのキーが選択されているか」の保持 | `state` |
| 「選択されたキーをどう動かすか」の計算 | `core/commands` |

判断に迷ったら「**ブラウザなしで意味を持つか**」で決めます。意味を持つなら `core`。

## 結果

得られるもの:

- `core` と `io` のテストが jsdom なしで動き、実行が速い
- アルゴリズムの検証に UI を描画する必要がなくなる
- ロジックの重複が起きにくい (置き場所が 1 つに決まる)
- 将来 CLI (「JSON を入力して info.json を出力する」) を作る場合、
  `core` と `io` をそのまま使える

諦めるもの:

- ファイル数が増える。小さな計算でも `core` に置くか UI に置くかを判断する手間がかかる
- ストアから直接データを触る方が短く書ける場面でも、コマンド関数を経由する必要がある

見直す条件: なし (この分離を緩める方向の変更は想定しません)。
