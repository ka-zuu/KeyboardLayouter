# ADR (Architecture Decision Record)

設計上の判断とその理由を記録します。**「なぜこうなっているのか」を後から
辿れるようにする**ためのもので、判断を変えるときの出発点になります。

## 運用ルール

- 1 ファイル 1 決定。ファイル名は `NNNN-短い英語の要約.md`。
- 状態は **採用 / 却下 / 破棄 (Superseded)** のいずれか。
- **既存の ADR は書き換えません。** 判断が変わったら新しい番号で ADR を追加し、
  古い方の先頭に `> 破棄: [NNNN](NNNN-....md) により置き換え` を追記します。
  決定の履歴自体が価値を持つためです。
- 以下に当てはまる変更は、実装の前に ADR を書きます。
  - 依存ライブラリの追加 (特に描画・状態管理・スキーマ検証)
  - レイヤ構成や依存方向の変更
  - データモデルの破壊的変更 (`schemaVersion` を上げる変更)
  - スコープの変更 (対象外としていた機能を作る、など)

## テンプレート

```markdown
# NNNN. 決定の要約

- 状態: 採用
- 日付: YYYY-MM-DD

## 背景

何を決める必要があるのか。制約は何か。

## 選択肢

### 案 A
### 案 B

## 決定

採用した案と、その理由。

## 結果

この決定によって何が楽になり、何を諦めたか。将来見直す条件。
```
