# KiCad

KiCad プロジェクト一式を zip で出力します。旧アプリでは回路図が実用レベル、
PCB はスイッチのフットプリント配置のみの未完成状態でした。
**本アプリでは PCB まで完成させます** (ネット・配線・ダイオード配置)。

| zip 内のファイル | 内容 |
|---|---|
| `<name>.kicad_pro` | プロジェクト設定 (JSON) |
| `<name>.kicad_sch` | 回路図 (S 式) |
| `<name>.kicad_pcb` | 基板 (S 式) |
| `README.md` | 開き方と、この出力でやっていないことの説明 |

## 前提と制約

- **マトリクスが全キーに割り当てられていること**が必要です。`matrix === null` の
  キーがある場合はエラーにして出力を中止します (無言で `ROW_0` に落とさない)。
- 1 スイッチにダイオード 1 個を直列に入れた構成のみを生成します。
- マイコン (Pro Micro 等)、コネクタ、LED、ロータリーエンコーダは生成しません。
  ユーザーが KiCad 側で追加します。`README.md` にその旨を明記します。
- 出力は「配線済みの回路図 + 部品が配置された基板」までです。基板外形
  (Edge.Cuts) と銅箔配線 (トラック) は生成しません。

## S 式の生成

外部ライブラリを使わず、文字列として組み立てます。ただし旧アプリのように
テンプレート文字列を素朴に連結するのではなく、**S 式のノードを表す小さな型**を
作ってから直列化します。

```ts
export type SExpr = string | number | SExpr[];

/** S 式を文字列化する。文字列は必要に応じて引用符で囲む。 */
export function formatSExpr(expr: SExpr, indent = 0): string;
```

理由: 旧アプリの `lib/kicad.ts` は生成後の文字列に対して
`.replace(/<[^>]+>/g, "")` `.replace(/`/g, "")` といった後処理を掛けていました。
これは生成側の不具合を出力の後始末で隠す形になっており、刻印に `<` や
バッククォートを含むレイアウトで壊れます。ノード → 文字列の一方向にすれば不要です。

### ファイル形式のバージョン

| ファイル | `version` |
|---|---|
| `.kicad_sch` | `20231120` |
| `.kicad_pcb` | `20240108` |
| `.kicad_pro` | `meta.version: 1` |

`generator` は本アプリの識別子にします。バージョンを上げるときは、
実際に KiCad で開いて確認してから変更してください。

## 回路図 (`.kicad_sch`)

### 構造

```
(kicad_sch (version 20231120) (generator "...")
  (paper "A4")
  (lib_symbols  ... シンボル定義を埋め込み ... )
  (wire ...)          ; Row / Col のバス
  (global_label ...)  ; ROW_0, COL_0 ...
  (symbol ...)        ; SW1, D1, SW2, D2 ...
  (wire ...)          ; スイッチ・ダイオードからバスへの引き出し
  (junction ...)      ; バスとの接続点
)
```

**シンボル定義 (`lib_symbols`) はファイル内に埋め込みます。**
外部ライブラリ (`kbd.kicad_sym` 等) への参照にすると、受け取った人の環境で
ライブラリが見つからず開けないためです。旧アプリと同じ方針です。

| シンボル | `lib_id` | 用途 |
|---|---|---|
| プッシュスイッチ | `kbd:SW_PUSH` | キースイッチ (自前定義) |
| ダイオード | `Device:D` | ゴースト対策 |

### トポロジ

`COL2ROW` の場合:

```
COL_n ──── SW ──── D(カソード→アノード) ──── ROW_m
```

`ROW2COL` の場合はダイオードの向きを反転させます。`meta.diodeDirection` に従います。

### 配置

キーの物理座標をそのまま回路図の格子に写します。1 キー 1 セル。

| 定数 | 値 | 意味 |
|---|---|---|
| グリッド | 1.27mm | すべての座標をこの倍数に丸める |
| 原点オフセット | (25.4, 25.4) mm | 図面左上の余白 |
| セル幅 | 30.48mm | キー 1 個分の横間隔 |
| セル高 | 25.40mm | キー 1 個分の縦間隔 |

セル内の配置 (セル左上を `(baseX, baseY)` とする):

| 要素 | 位置 |
|---|---|
| スイッチ | `(baseX + 10.16, baseY)` |
| ダイオード | `(baseX + 15.24, baseY + 7.62)`、90° 回転 |
| 列バス (縦線) | `x = baseX` |
| 行バス (横線) | `y = baseY + 15.24` |

- セル位置は `Math.round(key.position.x)` / `Math.round(key.position.y)` から求めます
  (回転や 0.25U のずれは回路図では意味を持たないため、格子に丸める)。
- 同じセルに 2 つ以上のキーが来た場合 (0.5U ずれの配列など) は、
  空きセルへ右方向にずらして配置し、警告を出します。旧アプリは重ねて描画していました。

### バスとラベル

- 行ごとに、その行に属するキーの最小列〜最大列を覆う横線を 1 本引き、
  左端に `ROW_m` のグローバルラベルを置きます。
- 列ごとに、同様の縦線と `COL_n` のグローバルラベルを置きます。
- スイッチ / ダイオードからバスへの引き出し線の先にジャンクションを置きます。

すべての `uuid` は `crypto.randomUUID()` で生成します。ただし**テストでは
乱数を固定**できるよう、UUID 生成関数を引数で受け取れるようにします
(ゴールデンファイル比較のため。旧アプリは `crypto.randomUUID()` を直接呼んでいて
出力が毎回変わり、テストで検証できませんでした)。

```ts
export interface KicadExportOptions {
  /** テストでは連番を返す実装を渡す。 */
  generateUuid?: () => string;
}
```

## 基板 (`.kicad_pcb`)

**ここが旧アプリで未完成だった部分です。**

### 生成するもの

| 要素 | 内容 |
|---|---|
| レイヤ定義 | 標準の 2 層基板 (F.Cu / B.Cu + ユーザーレイヤ) |
| ネットリスト | `(net 0 "")` から始まり、`ROW_m` / `COL_n` / スイッチ-ダイオード間の中間ネット |
| スイッチのフットプリント | 物理座標に配置。パッドにネットを割り当てる |
| ダイオードのフットプリント | スイッチの近傍に配置。パッドにネットを割り当てる |
| 回路図とのリンク | シンボルと同じ `uuid` を使い、`Reference` を一致させる |

### 座標と回転

```
xMm = key.position.x * 19.05 + 19.05 * key.size.w / 2   // キー中心
yMm = key.position.y * 19.05 + 19.05 * key.size.h / 2
```

- **フットプリントはキーの中心に置きます。** 旧アプリは左上座標をそのまま
  `(at x*19.05 y*19.05)` に渡していたため、キーが半キー分ずれていました。
- 回転角は**符号を反転**させます。KiCad の `(at x y angle)` は反時計回りが正、
  本アプリのモデルは時計回りが正です。
- 回転中心が幾何中心でない場合 (`rotation.origin !== null`) は、
  先に中心座標を回転させてから配置します。

### フットプリントの選択

| キーの寸法 | フットプリント |
|---|---|
| 1U | `Button_Switch_Keyboard:SW_Cherry_MX_1.00u_Plate` |
| 1.25U / 1.5U / 1.75U / 2U / 2.25U / 2.75U / 6.25U / 7U | 同シリーズの対応するもの (`SW_Cherry_MX_1.50u_Plate` 等) |
| 上記以外 | 最も近い寸法のものを選び、警告を出す |
| ダイオード | `Diode_SMD:D_SOD-123` |

フットプリント名は KiCad 標準ライブラリのものを参照します
(シンボルと違い、フットプリントは標準ライブラリにあるため埋め込みません)。
選択規則は `io/kicad/footprints.ts` の表に持たせ、ユーザーが将来
差し替えられるようにします。

### ダイオードの配置

スイッチの下 (`yMm + 8.0`) に既定で置きます。オプションで
「スイッチのソケット内側」「基板裏面」を選べるようにしますが、
最初のバージョンでは既定の 1 種類のみ実装します。

### 生成しないもの

- 基板外形 (Edge.Cuts) — キー配置から自動生成すると意図と合わないことが多いため
- 銅箔配線 (トラック) — ネットが付いていれば KiCad の自動配線・手配線で引けます
- ビア、ベタ塗り (Zone)、シルクの文字装飾

`README.md` にこれらを明記し、「回路図から基板を更新 (Update PCB from Schematic) を
実行して整合を確認してください」と案内します。

## 分割キーボード

`meta.split === true` のとき:

- 回路図は左右で別のシートに分けます (`<name>.kicad_sch` にルートシート、
  `left.kicad_sch` / `right.kicad_sch` を階層シートとして参照)。
- 基板は左右 1 枚ずつ、2 つの `.kicad_pcb` を出力します
  (`<name>_left.kicad_pcb` / `<name>_right.kicad_pcb`)。
- 座標は各側の AABB 左上を原点として正規化します。

## `.kicad_pro`

最小構成の JSON を出力します。

```json
{
  "meta": { "filename": "project.kicad_pro", "version": 1 },
  "board": { "page_layout": { "scale": 1 } },
  "schematic": { "page_layout": { "scale": 1 } }
}
```

## 検証

生成したファイルは、**KiCad で実際に開いて確認**する必要があります。
自動テストでできるのはここまでです。

| テスト | 内容 |
|---|---|
| ゴールデンファイル比較 | UUID を固定した上で `.kicad_sch` / `.kicad_pcb` の全文一致 |
| S 式の構文 | 括弧の対応が取れていること (簡易パーサでラウンドトリップ) |
| ネットの整合 | 回路図のネットと基板のネットの名前・数が一致すること |
| Reference の一意性 | `SW1`, `D1`, … に重複がないこと |
| リンク | 同じ論理部品の `uuid` が回路図と基板で一致すること |
| マトリクス未割り当て | エラーになって出力されないこと |
| 刻印の特殊文字 | `<`, `"`, バッククォート, 改行を含む刻印で壊れないこと |

`tests/fixtures/kicad/` にフィクスチャを置きます
(`4x4-macropad`, `ansi-104`, `split-ergo`, `special-chars`)。

手作業での確認手順は zip 内の `README.md` にも書き、リリース前チェックリスト
([../TESTING.md](../TESTING.md#リリース前の手作業確認)) に含めます。
