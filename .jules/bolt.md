## 2024-05-23 - React-Konva Component Splitting for Pan/Zoom Performance
**Learning:** In a React-Konva application, if the main `Stage` component subscribes to high-frequency state (like `pan` or `zoom`), it triggers a re-render of the entire component tree on every frame. Even if child components (like `KeyObject`) are memoized, the parent component still executes its render function, re-creating the React Element array (e.g., `keys.map(...)`). For large lists (1000+ items), this element creation and reconciliation overhead causes significant frame drops.
**Action:** Extract the list rendering into a separate component (e.g., `KeyList`) that ONLY subscribes to the data it needs (`project.keys`) and NOT the layout state (`pan`, `zoom`). The parent component renders `<KeyList />` which remains referentially stable during pan/zoom, allowing React to skip the entire list reconciliation process.
